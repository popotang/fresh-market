## 页面要解决的问题

让第一次进入项目的人在一屏内理解：

1. 数据从哪里来，经过什么链路，最后服务谁；
2. 现有系统不是概念图，哪些能力已经可点击使用；
3. 为什么有些数字是估算、为什么库存不能当实时全量；
4. 从哪里开始看经营数据。

## 页面结构

1. **首屏**
   - 标题：一张小票，如何变成明天的经营动作
   - 数据底座实时状态：最新营业日、统一指标数、成本覆盖、库存快照覆盖
   - 主入口：全局经营指标；次入口：老板驾驶舱、店长作战台

2. **业务数据怎么流动**
   - 超市收银 / 交易流水
   - 科迈云帆 SaaS / 现有业务系统
   - 私有化数据中心 / 汇聚 · 治理 · 留存
   - 云兔 AI 原生底座 / 统一指标 · Agent · 权限

3. **四类使用者**
   - 运营智能决策：选品 · 陈列 · 执行
   - 管理人员报表分析：经营趋势 · 异常归因
   - 大量业务人员：数据提取 · 辅助决策
   - 各类 Skill 自我沉淀：经验复用 · 持续迭代

4. **项目里已经有什么**
   - 业务数据集：47
   - 数据集关系：59
   - 统一指标：由 `businessMetricGateway` catalog 实时返回
   - 核心应用入口：老板驾驶舱、店长作战台、全局经营指标

5. **系统边界**
   - 不回写科迈
   - 估算毛利不是财务结算
   - 库存不是实时全量
   - 覆盖不足直接标注

6. **行动入口**
   - 先看全局指标
   - 进入店长作战台
   - 进入老板驾驶舱

## 数据与实现

- 只调用 `businessMetricGateway` 的 `catalog` 与 `health`，不直接查表。
