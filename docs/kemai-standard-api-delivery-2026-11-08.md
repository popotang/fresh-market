# 科迈同步架构升级：标准接口实现与验收

这是已实施范围和实测证据的记录，操作命令集中在[操作指引](kemai-pipeline-operations-2026-11-08.md)。本次按[开发计划](kemai-sync-development-plan-2026-11-08.md)先落地公共内核和零售纵向链路。**公共内核可运行，不代表采购详情、全部商品对象、Excel 数据首录和常驻运维已全部迁移。**

## 已落地的体系

OpenCLI 源捕获 → 私有不可变工件 → Python 确定性核对与批次 → Lovrabet CLI → 标准模型 API 事务。AI Skill 选择受控操作、判断证据，不承担事务或去重算法。

- 新网关 `kemaiSyncGateway`：`filter/aggregate/batchCreate/update/create` 加事务，未使用 Custom SQL 写业务数据。不同值更新受控逐条执行；没有把裸 `batchCreate` 冒充 upsert。
- 四张正式控制表：`sync_pipeline_streams/captures/batches/windows`。开始/失败日志独立记录；业务行、原始捕获、回执同事务；完整窗口与成功日志同事务。
- 稳定 capture/batch 身份、内容摘要、查询范围、上传日期口径；同 ID 不同内容拒绝；服务器回执解决超时未知写入。
- 单机新旧写入入口共同互斥、服务端按流事务控制行锁、全局源 gate、30 分钟冷却；分页未完成中断不能拼接另一快照。
- 状态/缺口查询、DB 历史核对、旧日志覆盖核验与承接、指定窗口补录、当前日临时增量、停机后有界追赶、恢复/放弃尝试、可选 30/60 分钟前台服务。
- 商品列表、基本详情、14 类页签与基础档案的独立 OpenCLI 命令；Excel 按精确任务下载、摘要校验、原子发布和崩溃恢复。源命令不持有数据库凭证。
- 两个 Skill 已更新；旧运行笔记中的进程 ID、日期覆盖和“13 条命令”不再作为当前状态。

本地最终回归为 142 项 Python 测试与 21 项 Node 测试，全部通过；测试数量以机器可读证据为准。

1. **标准接口隔离测试 18 项通过**：重复同回执、内容冲突拒绝、并发同批、并发冲突仅一方成功、父子写入回滚、窗口提交回滚、缺批拒绝、重试、行数和字节边界。

4. **空日闭环通过**：2026-10-01 零售流水真实查询空页，DB 计数为 0，成功提交空日证据；没有用 DB 空表代替源查询。
5. **历史覆盖承接**：按上传日期重新核对 99 个已记录源日，issues=[]，仅 29 次数据中心查询，无源站重扫；承接后的增量计划只有当前日与最近已闭日复访，不会重采全部历史。
6. **生产按流互斥通过**：零售订单采集期间，另一个 capture 在同一流发起开始，服务端返回 `STREAM_BUSY_RESUME_ACTIVE_CAPTURE`，未创建竞争采集。

零售订单 2026-11-07 的 5,228 条也已全部提交（6 页、228 批），再次以源操作预算 0 重放同一 capture 成功。业务键缺失/额外均为 0，业务内容差异为 0。由于开发期间启用查询时间等价规则，前 2,642 条实际更新了原始载荷，后 2,586 条仅 `gmtOperation` 不同而未重写；新增为 0。导出总数复用了源站明确返回的 24 小时内原任务，证据按复用口径标注。

## 实测后修正的问题

- **JS 运行预算**：平台脚本有 1,000,000 语句限制；最初的纯 JS SHA-256 在真实大记录批次超限。优化计算后才通过实际批次，不能只凭两行样本认定容量成立。
- **真实记录大小**：普通测试表能批量新增 200 行约 1.32 秒；200 行不同值更新约 9.46 秒。真实流水每行较大，48 KB 预算下通常每批约 19 行。硬上限是 200 行且 records JSON ≤64,000 UTF-8 字节，任何一项超出均拒绝；不是所有数据都能一次写 200 行。
- **轻量观察**：源与 DB 原始摘要一致时，只提交稳定键和预期摘要，服务端同时核对业务行及原始捕获；源完整工件不丢弃，已有批次不重新分组。
- **查询时间差异**：流水页面 `timeType=1`、订单页面 `dateType=0` 才是上传时间。两者的值 2 都表示当班日期。新内核使用 `source_created_at` 分窗，保留 `sold_at` 做销售分析；迟上传销售归入上传日增量。
- **上传时间索引**：缺索引导致标准 API 日计数超时。已通过 mycli 在线新增两条 `(tenant_id,source_created_at)` 索引，读回存在；目标两表 DB 分析任务成功，差异刷新未返回待分析项。SQL 仅用于 DDL，业务写入仍是标准接口。
- **异步导出真实返回**：旧页面按钮不返回 Promise，会吞掉实际拒绝原因。新适配器观察底层导出 Promise，识别 HTTP 200 业务失败/限流，并在结束后恢复页面方法。
- **源站 24 小时导出去重**：科迈返回已有任务号。只复用它明确指定的任务，不选择“最新相似任务”；保存 `server_24h_dedup`、原导出创建时间和 `reused_export_total_and_capture`，不能声称生成了新导出快照。
- **订单 `gmtOperation`**：样本中该字段等于每次查询页的执行时刻。仅该顶层字段变化且其余原始字段完全一致、业务/原始捕获摘要相符时，不重写业务及原始捕获行；完整新快照仍保存在工件中。回执标记 `metadata_only_unchanged`，审核区分原始摘要差异和业务差异；任何其他字段变化仍更新。
- **恢复时旧状态覆盖**：外层失败日志改为重读最新 manifest，避免覆盖刚提交的批次回执。导出等待、失败和冷却有日志，成功水位不会被失败清除。
